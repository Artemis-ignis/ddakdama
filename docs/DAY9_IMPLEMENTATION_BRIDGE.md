# Day9 구현 브리지

Day9 강의의 구현 순서인 `화면 → 흐름 → 저장 → 로그인 → API → 배포`를 딱담아 공개 베타에 맞춰 적용한 기록입니다.

## 화면

- 자연어·붙여넣기·브라우저 음성 입력을 받는 목록 화면
- 모호한 품목만 큰 선택지 카드로 되묻는 확인 화면
- 후보 상품·규격·판매단위·수량·예상 상품가를 확인하는 장바구니 화면
- 화면 하단의 AI 장보기 도우미

## 흐름

1. 사용자가 상품 목록을 입력합니다.
2. 규칙 또는 Gemini가 모호한 품목의 질문과 선택지를 만듭니다.
3. 사용자가 선택지 또는 직접 입력으로 답합니다.
4. 답변이 반영된 목록만 상품 후보 조회로 넘어갑니다.
5. 사용자가 후보와 수량을 확인하고 쿠팡 상품 페이지 또는 확장프로그램·Android로 이어갑니다.

## 저장·접근 제어

- 계획 본문은 Worker Durable Object에 최대 24시간 TTL로 저장합니다. GPT grant와 Android claim은 별도의 짧은 capability이며 기본 15분입니다.
- 계획 링크는 익명 capability이며, 로그인·비밀번호·쿠팡 쿠키·결제정보를 저장하지 않습니다.
- 만료된 계획은 읽기와 Android claim 모두 차단합니다.
- 음성 원본은 저장하지 않습니다. 계획 링크의 입력 원문은 기본적으로 마스킹하고, 사용자가 명시적으로 동의한 경우에만 최대 24시간 보관합니다.

## API

- `POST /api/plans`
- `POST /api/plans/:id/clarify`
- `POST /api/plans/:id/resolve`
- `POST /api/plans/:id/preflight`
- `POST /api/executions`는 계획 버전·사전 검토·사용자 명시 승인을 요구합니다.
- `POST /api/events`는 원문·음성 없이 세션 ID와 허용된 이벤트만 익명으로 기록합니다.

AI는 질문과 구조화 초안만 제안합니다. 가격·재고·배송·총액·장바구니 수량은 공통 모델과 검증 코드가 계산합니다.

## 배포 전 확인

웹·Worker·Chrome 확장·Android가 같은 계획 모델과 24시간 TTL을 사용하도록 타입체크와 통합 테스트를 통과시킨 뒤, HTTPS origin·`/health`·개인정보처리방침·이용약관·지원 페이지를 확인합니다. 결제·주문 확정은 공개 베타 범위에 포함하지 않습니다.
